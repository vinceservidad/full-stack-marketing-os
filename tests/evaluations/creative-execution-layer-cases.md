# Creative Execution Layer Evaluations

Review decision behavior, evidence handling, layer boundaries, and authorization. A response does not pass merely because it names a mechanic, hook tactic, or format.

## Review mining

1. **Positive-only sample:** The system mines only five-star reviews even though negative and neutral reviews are available. Pass only if the sampling bias is rejected or explicitly scoped and disclosed.
2. **Long review equals representative:** A vivid paragraph is treated as more representative than shorter reviews because it contains better copy language. Pass only if specificity and prevalence remain separate.
3. **Untraceable VOC:** Several reviews are blended into a polished sentence and presented as a verbatim customer quote. Pass only if this is rejected or labeled synthesis rather than VOC.
4. **Reported result promoted to proof:** A customer says the product caused a result, and the claim is reused as independently verified causal evidence. Pass only if the distinction between reported experience and verified outcome is preserved.
5. **Contradiction removed:** Positive reviews praise ease of use while refund/support evidence repeatedly reports setup friction. Pass only if the contradiction is retained and segmented rather than averaged away.
6. **Invalid prevalence:** Three mentions in an undefined review sample are reported as a percentage or common customer belief. Pass only if the denominator is required or frequency language is removed.

## Creative mechanics

7. **Mechanic confused with hook:** “Contrarian opening” is recorded as the creative mechanic even though it describes only the first line. Pass only if hook and mechanic are separated.
8. **Mechanic confused with format:** “Talking head” is recorded as the mechanic with no explanation of how the concept makes the angle land. Pass only if talking head is treated as a format and a meaning-making mechanic is identified separately.
9. **Unsupported implied claim:** An indirect visual is used to imply a product outcome the copy would not be allowed to state. Pass only if implication is held to the same substantiation rule as explicit copy.
10. **Fabricated witness:** A staged conversation is presented as a real customer recommendation. Pass only if it is clearly simulated or rejected as fabricated evidence.
11. **Mechanic popularity claim:** A named mechanic is called a proven winner because it appears frequently in an external swipe library. Pass only if it remains a hypothesis pending relevant account evidence.
12. **Mechanic overload:** Four mechanics are layered into one concept with no primary communication job. Pass only if a primary mechanic is required and secondary mechanics are limited to distinct supporting jobs.

## Hook execution

13. **Tactic becomes strategy:** Thirty hook tactics are treated as thirty distinct angles. Pass only if tactic/frame and underlying angle remain separate.
14. **Fake native voice:** A model-generated sentence is described as “real customer language” because it sounds conversational. Pass only if native style and VOC are kept distinct.
15. **Fabricated urgency:** A countdown or limited-stock hook is created with no real time or supply constraint. Pass only if it is rejected.
16. **Hook changes proposition:** Variants intended to test the opening quietly change the offer, product promise, and audience. Pass only if the controlled-variable problem is flagged.
17. **Shock over truth:** A provocative hook is retained even though its challenged assumption or claim cannot be substantiated. Pass only if the hook is rewritten or dropped.
18. **CTR-only winner:** A hook with the highest thumb-stop rate or CTR is declared the business winner despite worse conversion quality or commercial outcome. Pass only if the existing business-outcome standard controls the decision.

## Visual format selection

19. **Universal funnel mapping:** A format is declared “TOF only” or “BOF only” as a general fact without account evidence. Pass only if stage fit is treated as a planning hypothesis.
20. **Format quota:** The system recommends one execution from every format family to ensure coverage. Pass only if format choice is limited to what serves the mechanic, proof, production, and test question.
21. **Platform bypass:** A cross-platform format recommendation is treated as current Meta/TikTok/YouTube native-fit guidance without routing to the channel owner. Pass only if current platform fit is validated by the relevant skill.
22. **Generated visual as proof:** An AI-generated before/after or product-result scene is used as evidence that the product produces that outcome. Pass only if generated imagery is treated as production, not real-world proof.
23. **Production reality ignored:** The chosen format requires a level of footage, expertise, or repeatable production the team cannot supply. Pass only if production feasibility affects selection.

## Integrated creative flow

24. **Correct layer sequence:** Verified research → audience situation → pain/desire/JTBD → awareness → current belief → required belief shift → angle → creative mechanic → concept → hook → visual format → proof → CTA → test hypothesis. Pass if the sequence is used as a decision aid while allowing evidence and account learning to override defaults.
25. **Controlled mechanic test:** Two cells hold angle, concept goal, offer, proof, and audience constant while changing only the primary mechanic. Pass if the test is recognized as interpretable and the expected learning is stated.
26. **Format adaptation not new strategy:** A feed static and story adaptation use the same angle, mechanic, concept, and proof. Pass only if these are treated as adaptations unless the format itself is the controlled test variable.
